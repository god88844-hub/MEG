# Security Policy

Report vulnerabilities privately through [GitHub security advisories](https://github.com/god88844-hub/MEG/security/advisories/new). Include reproduction steps and the affected commit/version. Never include real API keys in reports or public issues.

## Verified Boundaries

- **Local-first & BYOK:** Local inference uses your configured server; cloud inference transmits conversation context and tool observations to the provider you select. Remote plaintext `http://` endpoints are blocked by default (only loopback `localhost`/`127.0.0.1`/`::1` allows HTTP unless `MEG_ALLOW_INSECURE_HTTP=1` is set). Gemini native requests send credentials strictly in the `x-goog-api-key` header (never in URL query strings).
- **Cross-OS credential vault:** API keys are stored in **Windows Credential Manager** on Windows, **macOS Keychain** (`/usr/bin/security`, secrets passed via stdin) on macOS, and **Linux Secret Service** (`secret-tool`, secrets passed via stdin) on Linux, with a symlink-checked `0600` atomic `vault.json` fallback in headless environments. Keys are never written to `providers.json` or session transcripts and are masked in UI inputs.
- **Workspace & secret airlock:** Native file tools (`read_file`, `write_file`, `edit_file`, `grep_files`, `search_files`) enforce symlink TOCTOU checks, confine paths to the selected workspace, block `.env*` files, and scrub detected secret patterns from observations and `@` attachments.
- **Plan mode & delegated workers:** Plan mode and `meg worker` block mutating native tools at the execution boundary. Note: external MCP `readOnlyHint` annotations remain trusted server metadata, not external-process enforcement.
- **Act mode OS sandboxing:** Act mode enforces `.meg/permissions.json` (`deny` > `allow` > `ask` with fail-closed `Ask`), scrubs ambient secret environment variables (`*_API_KEY`, `*_SECRET`, `*_TOKEN`, `MEG_RECEIPT_KEY`, `MEG_TUI_API_KEY`, etc.), and applies OS confinement:
  - **Windows (`MEG_SANDBOX=strict`):** Spawns commands inside a per-workspace **Windows AppContainer** (`CreateAppContainerProfile` + `PROC_THREAD_ATTRIBUTE_SECURITY_CAPABILITIES`) with filesystem write ACLs granted strictly to the workspace directory, drops network capability SIDs + enforces loopback proxy sinkhole when `network: false`, restricts inherited handles via `PROC_THREAD_ATTRIBUTE_HANDLE_LIST`, and attaches processes to a resource/UI-limited Job Object (`ActiveProcessLimit`, `JobMemoryLimit`, `JobObjectBasicUIRestrictions`) prior to thread resume. Persistent `shell_session` is disabled in `strict` mode.
  - **Linux:** Bubblewrap (`bwrap`) with `--unshare-pid --new-session --die-with-parent`, read-only root/system binds, writable workspace + `/tmp`, optional `--unshare-net`, and automatic AppArmor unprivileged-userns probe.
  - **macOS:** `/usr/bin/sandbox-exec` Seatbelt profile with canonical workspace subpaths and optional `(deny network*)`.
  - For hostile/untrusted repositories requiring defense-in-depth beyond host OS sandboxes, run inside a container or VM.
- **Loopback daemon authentication (`meg serve` / `meg attach`):** `meg serve` binds strictly to `127.0.0.1` and requires a per-launch 256-bit constant-time-verified bearer token on every connection (disconnecting after 3 failed auth attempts). `meg attach` refuses non-loopback addresses by default unless `MEG_ATTACH_ALLOW_REMOTE=1` is explicitly set.
- **MCP trust & supply-chain:** New or modified MCP servers require explicit start/trust. Both `PATH`-resolved interpreters and script arguments are SHA-256 hash-pinned into the trust fingerprint (tampering invalidates auto-reconnect), and ambient host secrets are scrubbed before spawning stdio MCP servers. Third-party `SKILL.md` files are screened by the DDIPE supply-chain scanner across both `read_skill` and `/skills`.
- **CI & provenance:** Cross-platform CI runs strict zero-warning Clippy (`-D warnings`) and locked Rust workspace tests on Ubuntu, macOS, and Windows plus Python offline evals. Tagged releases publish `SHA256SUMS.txt` checksums verified fail-closed by both `scripts/install.ps1` and `scripts/install.sh`. Independent third-party security audits have not been performed.
