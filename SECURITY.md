# Security Policy

Report vulnerabilities privately through [GitHub security advisories](https://github.com/god88844-hub/MEG/security/advisories/new). Include reproduction steps and the affected commit/version. Never include real API keys in reports or public issues.

## Verified Boundaries

- **Local-first & BYOK:** Local inference uses your configured server; cloud inference transmits conversation context and tool observations to the provider you select. Remote plaintext `http://` endpoints are blocked by default (only loopback `localhost`/`127.0.0.1`/`::1` allows HTTP unless `MEG_ALLOW_INSECURE_HTTP=1` is set).
- **Credential storage:** On Windows, API keys are stored in Windows Credential Manager (never written to JSON settings or session transcripts) and masked in UI inputs. Non-Windows platforms use environment variables.
- **Workspace & secret airlock:** Native file tools (`read_file`, `write_file`, `edit_file`, `grep_files`, `search_files`) confine paths to the selected workspace, block `.env*` files, and scrub detected secret patterns from observations and `@` attachments.
- **Plan mode & delegated workers:** Plan mode and `meg worker` block mutating native tools at the execution boundary. Note: MCP `readOnlyHint` annotations remain trusted server metadata, not external-process enforcement.
- **Act mode OS sandboxing:** Act mode enforces `.meg/permissions.json` (`deny` > `allow` > `ask`), scrubs ambient secret environment variables (`*_API_KEY`, `*_SECRET`, `*_TOKEN`, `MEG_RECEIPT_KEY`, `MEG_TUI_API_KEY`, etc.), and applies OS confinement: Linux `bwrap` (`--unshare-pid --new-session --die-with-parent` + `--unshare-net` when `network: false`), macOS `sandbox-exec` Seatbelt, and Windows Job Objects (`ActiveProcessLimit`, `JobMemoryLimit`, UI restrictions, `CreateRestrictedToken` probe in `strict` mode, and loopback proxy sinkhole when `network: false`). For untrusted/hostile repositories on Windows, run inside a container or VM.
- **MCP trust & supply-chain:** New or modified MCP servers require explicit start/trust. Both `PATH`-resolved interpreters and script arguments are SHA-256 hash-pinned into the trust fingerprint (tampering invalidates auto-reconnect), and ambient host secrets are scrubbed before spawning stdio MCP servers. Third-party `SKILL.md` files are screened by the DDIPE supply-chain scanner across both `read_skill` and `/skills`.
- **CI & provenance:** Cross-platform CI runs Rust tests and strict zero-warning Clippy on Windows, Linux, and macOS plus Python offline evals. Tagged releases publish `SHA256SUMS.txt` checksums verified fail-closed by the installer scripts. Independent third-party security audits have not been performed.
